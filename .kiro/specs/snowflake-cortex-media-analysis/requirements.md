# Requirements Document

## Introduction

This specification defines the Snowflake Cortex-only media-analysis provider. The provider supplies normalized image analysis, video-frame analysis, tagging, captions, embeddings, and audio transcription to the application integration layer. Audio transcription SHALL use Snowflake Cortex `AI_TRANSCRIBE`; no alternate production transcription provider is included.

## Glossary

- **Cortex_Provider**: Provider adapter that invokes Snowflake Cortex and returns normalized results.
- **Cortex_Client**: Authenticated client that executes Cortex functions with bound parameters.
- **Media_Artifact**: Validated image, frame, or audio object referenced from object storage.
- **Cortex_Transcription**: Transcription performed through `AI_TRANSCRIBE`.
- **Embedding**: Fixed-dimension vector generated by a Cortex embedding function/model.
- **Prompt_Version**: Immutable identifier for a structured Cortex prompt/template.

## Requirements

### Requirement 1: Cortex client

**User Story:** As a platform operator, I want a secure Cortex client, so that AI calls use controlled credentials and predictable failure behavior.

#### Acceptance Criteria

1. THE Cortex_Client SHALL execute configured Cortex functions with parameter binding.
2. THE Cortex_Client SHALL apply connection and operation timeouts.
3. THE Cortex_Client SHALL classify authentication, authorization, capability, transient, validation, and permanent content failures.
4. THE Cortex_Client SHALL redact credentials, signed URLs, and raw media from logs.
5. WHEN a Cortex function is unavailable, THE Cortex_Client SHALL return a capability error with a remediation category.

### Requirement 2: Image and frame analysis

**User Story:** As a user, I want visual media analyzed, so that saved posts receive captions and tags.

#### Acceptance Criteria

1. WHEN a valid image is submitted, THE Cortex_Provider SHALL return normalized caption, tag, observation, warning, provider, and model fields.
2. WHEN valid representative frames are submitted, THE Cortex_Provider SHALL return per-frame results and an aggregate description.
3. THE Cortex_Provider SHALL preserve each input frame timestamp in the corresponding result.
4. THE Cortex_Provider SHALL enforce configured frame count, payload, and media-size limits.
5. IF a Cortex response fails schema validation, THEN THE Cortex_Provider SHALL reject the response and classify the operation as a response error.

### Requirement 3: Cortex transcription

**User Story:** As a user, I want audio and video speech transcribed, so that spoken content can be searched.

#### Acceptance Criteria

1. WHEN a valid audio artifact is submitted, THE Cortex_Provider SHALL invoke Snowflake Cortex `AI_TRANSCRIBE`.
2. THE Cortex_Provider SHALL normalize transcription text, language, segments, provider, and model fields.
3. WHEN `AI_TRANSCRIBE` returns timestamps, THE Cortex_Provider SHALL preserve ordered start and end times.
4. WHEN `AI_TRANSCRIBE` returns no timestamps, THE Cortex_Provider SHALL create a valid fallback segment representation.
5. IF the Snowflake account lacks `AI_TRANSCRIBE` capability or permission, THEN THE Cortex_Provider SHALL return a capability/configuration error.
6. THE Cortex_Provider SHALL not invoke a fallback transcription provider.
7. THE Cortex_Provider SHALL preserve a bounded redacted raw provider response.

### Requirement 4: Embeddings

**User Story:** As a user, I want semantic search, so that posts can be found without exact wording.

#### Acceptance Criteria

1. WHEN valid caption, transcript, tag, or media-description text is submitted, THE Cortex_Provider SHALL return an embedding.
2. THE Cortex_Provider SHALL return model, model version when available, dimension, and vector values.
3. THE Cortex_Provider SHALL reject empty, non-finite, truncated, padded, or dimension-invalid vectors.
4. THE Cortex_Provider SHALL support separate embedding model/version metadata for re-embedding.
5. IF embedding generation fails transiently, THEN THE Cortex_Provider SHALL apply bounded retry policy.

### Requirement 5: Input validation and security

**User Story:** As an operator, I want safe media inputs, so that analysis cannot exhaust resources or leak private data.

#### Acceptance Criteria

1. THE Cortex_Provider SHALL validate content type, byte size, duration, artifact accessibility, and prompt version before invocation.
2. THE Cortex_Provider SHALL use short-lived signed access or controlled byte transfer for private artifacts.
3. THE Cortex_Provider SHALL enforce configured request and concurrency limits.
4. IF an artifact is invalid or inaccessible, THEN THE Cortex_Provider SHALL reject the input without invoking Cortex.
5. THE Cortex_Provider SHALL use least-privilege Snowflake credentials and configuration.

### Requirement 6: Provider testability

**User Story:** As a developer, I want a provider contract suite, so that Cortex behavior can be validated independently of TiDB.

#### Acceptance Criteria

1. THE Cortex_Provider SHALL have fixture tests for valid image, frame, transcription, and embedding responses.
2. THE Cortex_Provider SHALL have tests for malformed responses, unsupported media, capability errors, permission errors, throttling, timeouts, and empty transcripts.
3. THE Cortex_Provider SHALL have at least one approved live integration test for `AI_TRANSCRIBE`.
4. THE Cortex_Provider SHALL expose a fake client for deterministic retry and failure tests.
5. THE Cortex_Provider SHALL expose capability status for startup and health checks.
